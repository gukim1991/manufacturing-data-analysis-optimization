### 2.3 MILP 모델 명세

#### 2.3.1 집합(Sets)

| 기호 | 의미 |
|---|---|
| $J$ | 모든 Job 집합 |
| $O_j$ | Job $j$의 Operation 집합 (순서 보존) |
| $M$ | 기계 집합 |
| $M(o)$ | Operation $o$가 사용 가능한 기계 집합 (`machine_type` 기준) |
| $\mathcal{B}$ | BOM 종속쌍 $(j_{BULK}, j_{FG})$ 집합 |

#### 2.3.2 파라미터(Parameters)

| 기호 | 의미 |
|---|---|
| $p_o$ | Operation $o$의 처리 시간 |
| $d_j$ | Job $j$의 납기 |
| $r_j$ | Job $j$의 release 시점 |
| $H$ | Big-M 상수 (= horizon) |

#### 2.3.3 결정 변수(Decision Variables)

| 변수 | 도메인 | 의미 |
|---|---|---|
| $s_o$ | $\mathbb{R}_{\ge 0}$ | Operation $o$의 시작 시점 |
| $x_{o,m}$ | $\{0,1\}$ | Op $o$가 기계 $m$에 배정되면 1 |
| $y_{o,o',m}$ | $\{0,1\}$ | 기계 $m$에서 $o$가 $o'$보다 먼저면 1 |
| $C_{max}$ | $\mathbb{R}_{\ge 0}$ | Makespan |
| $T_j$ | $\mathbb{R}_{\ge 0}$ | Job $j$의 Tardiness |

#### 2.3.4 제약(Constraints)

**C1. 기계 배정 (각 Op은 정확히 1대에 배정)**
$$\sum_{m \in M(o)} x_{o,m} = 1 \quad \forall o$$

**C2. Release**
$$s_o \ge r_{j(o)} \quad \forall o$$

**C3. Job 내 선후행**
$$s_{o_{i+1}} \ge s_{o_i} + p_{o_i} \quad \forall j, \, i \in [0, |O_j|-2]$$

**C4. 기계 disjunctive (Big-M, 비선점)**
$$s_{o'} \ge s_o + p_o - H(1 - y_{o,o',m}) - H(2 - x_{o,m} - x_{o',m})$$
$$s_o \ge s_{o'} + p_{o'} - H \cdot y_{o,o',m} - H(2 - x_{o,m} - x_{o',m})$$
$$\forall m, \, \forall o \ne o' \text{ with } m \in M(o) \cap M(o')$$

**C5. BOM 종속** (반제품 마지막 시험 op $\prec$ 완제품 첫 충전 op)
$$s_{o_{FG,0}} \ge s_{o_{BULK,last}} + p_{o_{BULK,last}} \quad \forall (j_B, j_F) \in \mathcal{B}$$

**C6. 저장조 용량** (동시점 동시 점유 ≤ STORAGE 대수) — 시간 슬라이스 근사 또는 Pinedo 식 사용

**C7. Makespan / Tardiness**
$$C_{max} \ge s_{o_{j,last}} + p_{o_{j,last}} \quad \forall j$$
$$T_j \ge s_{o_{j,last}} + p_{o_{j,last}} - d_j \quad \forall j$$

#### 2.3.5 목적함수

$$\min \;\; \alpha \cdot C_{max} + \beta \cdot \sum_j T_j$$

### 2.4 Dispatching Rules 명세

#### 2.4.1 공통 인터페이스
```python
# solver/dispatching_solver.py
class DispatchingRule(Enum):
    SPT  = "SPT"   # Shortest Processing Time
    LPT  = "LPT"   # Longest Processing Time
    EDD  = "EDD"   # Earliest Due Date
    FIFO = "FIFO"
    CR   = "CR"    # Critical Ratio = (due - now) / remaining_work

class DispatchingSolver(BaseSolver):
    def __init__(self, rule: DispatchingRule): ...
    def solve(self, instance: Instance) -> Schedule:
        """SimPy 가상공장 실행 + 규칙에 따라 실시간 dispatch"""
```

#### 2.4.2 의사결정 시점
- SimPy 자원이 free 가 되는 매 시점 (`yield resource.release()` 직후)
- 해당 기계에 대기 중인 Operation 들에 대해 rule 적용 → 최우선 Op 선택

#### 2.4.3 우선순위 함수
| 규칙 | 우선순위 score (작을수록 우선) |
|---|---|
| SPT | $p_o$ |
| LPT | $-p_o$ |
| EDD | $d_{j(o)}$ |
| FIFO | release 시점 |
| CR | $\frac{d_{j(o)} - now}{\sum_{o' \in O_{j}, o' \succeq o} p_{o'}}$ |

### 2.5 DRL (PPO + Action Masking) 명세

#### 2.5.1 환경 — Gymnasium API
```python
# solver/drl_solver.py
class JSSPEnv(gym.Env):
    def __init__(self, instance: Instance, max_steps: int = 1000): ...
    def reset(self, seed=None) -> Tuple[ObsDict, dict]: ...
    def step(self, action: int) -> Tuple[ObsDict, float, bool, bool, dict]: ...
    def action_mask(self) -> np.ndarray: ...   # shape: (n_actions,)
```

#### 2.5.2 상태(Observation)

| 필드 | shape | 설명 |
|---|---|---|
| `job_features` | (J, 5) | per-job: 잔여 op 수, 잔여 처리시간, 납기 여유, release 경과, BOM 준비도 |
| `machine_features` | (M, 3) | per-machine: 다음 가용 시점, 현재 점유 Op 잔여시간, type one-hot |
| `bom_link` | (J, J) | 인접 행렬 (BOM 종속) |
| `time` | () | 현재 시뮬레이션 시각 |

#### 2.5.3 행동(Action) — Job × Machine 매트릭스 평탄화
- $a \in \{0, 1, \dots, J \times M - 1\}$
- $a = j \cdot M + m$ → "Job $j$의 다음 Operation을 Machine $m$에 즉시 배정"

#### 2.5.4 Action Masking
| 마스킹 조건 | 사유 |
|---|---|
| Job $j$의 다음 op 가 없음 | 완료 Job |
| Machine $m$의 타입이 op 의 machine_type 과 불일치 | 라우팅 위반 |
| Machine $m$이 현재 점유 중 | 기계 용량 |
| 직전 op 이 미완료 | 선후행 위반 |
| BOM 부모 BULK 의 QC_BULK 미완료 | BOM 종속 (FG only) |
| 저장조 모두 점유 (STORAGE op) | 용량 ⑤ |

#### 2.5.5 보상(Reward)
- step reward = $-\Delta C_{max}^{lower\_bound}$ (makespan LB 증가분의 음수)
- terminal bonus = $-(\alpha C_{max} + \beta \sum T_j)$
- 사용 알고리즘: **PPO** (Stable-Baselines3, `MaskablePPO` from `sb3-contrib`)

#### 2.5.6 학습 파이프라인
```python
from sb3_contrib import MaskablePPO
from sb3_contrib.common.maskable.utils import get_action_masks

def train(instances: List[Instance], total_timesteps: int = 1_000_000):
    env = make_vec_env(lambda: JSSPEnv(random.choice(instances)), n_envs=8)
    model = MaskablePPO("MultiInputPolicy", env, gamma=0.99, ...)
    model.learn(total_timesteps=total_timesteps)
    return model
```

#### 2.6.2 프로세스 함수 시그니처
```python
# simulator/processes.py

def bulk_job_process(env: simpy.Environment,
                     job: Job,
                     resources: FactoryResources,
                     scheduler: "BaseScheduler",
                     log: ExecutionLog) -> Generator:
    """
    원료계량 → 배합 → 시험 → 배출 순으로 진행.
    scheduler.next_machine(op) 로 어떤 기계에 들어갈지 결정.
    """
    yield env.timeout(job.release)
    for op in job.operations:
        machine = yield env.process(scheduler.acquire(env, op, resources))
        with machine.request() as req:
            yield req
            start = env.now
            yield env.timeout(op.proc_time)
            log.record(Assignment(op, machine, start, env.now))

def fg_job_process(env, job, resources, scheduler, log, bom_event: simpy.Event):
    """FG Job 은 BOM 부모 BULK 의 QC_BULK 완료 이벤트를 기다림."""
    yield bom_event
    yield env.timeout(max(0, job.release - env.now))
    for op in job.operations:
        ... # 위와 동일 패턴

def factory_main(env, instance, scheduler):
    """모든 Job 프로세스 spawn + BOM 이벤트 와이어링"""
    bom_events: Dict[str, simpy.Event] = {}
    for j in instance.jobs:
        if j.type == JobType.BULK:
            bom_events[j.id] = env.event()
            env.process(bulk_job_process(..., bom_events[j.id]))
    for j in instance.jobs:
        if j.type == JobType.FG:
            parent_evt = bom_events[j.bom_parent_id]
            env.process(fg_job_process(..., parent_evt))
```

## 3. 설계 의사결정 요약

| 결정 사항 | 선택 | 사유 |
|---|---|---|
| 기계 표현 | `Resource` per machine instance | 동일 type 내 capacity 분배가 명확 |
| 비선점 | 명시 제약 없음 (yield 도중 interrupt 안 함) | SimPy 기본 동작이 비선점 |
| BOM 종속 | `simpy.Event` 와이어링 | MILP / DRL 양쪽에서 일관 표현 가능 |
| 저장조 | `Container` (수량) + per-batch occupancy tracking | 숙성시간 모델링 용이 |
| DRL framework | Gymnasium + `sb3-contrib MaskablePPO` | Action mask 네이티브 지원 |
| MILP solver | PuLP + CBC (기본) / Gurobi (옵션) | 무료 + 학교 라이센스 양쪽 대응 |
| 검증 | `Schedule.validate()` 가 모든 제약 사후 검사 | Solver bug 조기 발견 |
